FALLO 1 — NO SE PUEDEN CREAR FACTURAS
--------------------------------------------------------------------------------
Qué pasa:
  En "Nueva factura" el desplegable de clientes sale vacío. Sin cliente no se
  puede emitir la factura, así que la pantalla queda inservible.

Endpoint que falta:
  GET /cliente/listar-ultimos

Quién lo llama:
  facturacion360/src/main/resources/static/facturas.js
    línea   4 : const RUTA_CLIENTES = "/cliente/listar-ultimos?limite=100";
    línea 162 : const respuesta = await fetch(RUTA_CLIENTES);

OJO CON EL CÓDIGO DE ERROR: devuelve 400, no 404.
  La ruta encaja en @GetMapping("/{id}") de ClienteController, que declara
  @PathVariable int id (línea 316). Spring captura la petición, intenta convertir
  "listar-ultimos" a int, falla con MethodArgumentTypeMismatchException, y como
  ManejadorExcepciones no tiene handler para esa excepción sale el 400 por
  defecto.

  Por eso ha pasado desapercibido: un 404 dice "esta ruta no existe" y te manda
  al backend; un 400 parece "has mandado mal los parámetros" y te manda a mirar
  el JavaScript, donde no hay nada que arreglar.

Dónde se perdió:
  El método desaparece en 8d1116e (14/09 12:42) y entra en master con el merge
  fc59340 (14/09 12:43, PR #12). Comprobación de los dos padres del merge:
    padre 1 (master)  c5e3259 -> SÍ tenía el método
    padre 2 (rama)    8d1116e -> NO lo tenía
    resultado del merge      -> NO lo tiene
  El conflicto se resolvió con la versión de la rama.

Nota, porque es la lección del caso:
  El endpoint estaba marcado @Deprecated, y probablemente por eso se dio por
  prescindible. Pero el javadoc decía explícitamente lo contrario (línea 99 del
  fichero antes del borrado):

    "Este endpoint sigue funcionando y con sus pruebas: obsoleto no es lo mismo
     que roto. Se mantiene porque es con el que se montó el listado."

  @Deprecated significa "no lo uses en código nuevo", no "esto sobra". Y aquí
  había código nuevo usándolo: la llamada de facturas.js la escribió Fran el
  01/09 en el commit 15e22e08.

Lo que SÍ sigue existiendo (verificado en origin/master, no hay que tocarlo):
  ClienteService.listarUltimos(int)       declarado      ClienteService.java:27
  ClienteServiceImpl.listarUltimos(int)   implementado   ClienteServiceImpl.java:51
  LIMITE_MIN = 1                          ClienteController.java:74

  clienteService / clienteMapper          ClienteController.java:84 y 87

CÓMO ARREGLARLO
  Fichero: .../controller/ClienteController.java
  Añadir el método. No hace falta ningún import nuevo:

    @Deprecated
    @GetMapping("/listar-ultimos")
    public ResponseEntity<List<ClienteResponse>> listarUltimos(
            @RequestParam(defaultValue = "10") int limite) {

        ResponseEntity<List<ClienteResponse>> respuestaHttp = null;

        int limiteSeguro = Math.max(LIMITE_MIN, Math.min(LIMITE_MAX, limite));
        log.info("GET /cliente/listar-ultimos?limite={} (acotado a {})",
                limite, limiteSeguro);

        try {
            List<Cliente> ultimos = clienteService.listarUltimos(limiteSeguro);
            List<ClienteResponse> respuesta = ultimos.stream()
                    .map(clienteMapper::toResponse).toList();
            log.info("GET /cliente/listar-ultimos -> 200 ({} clientes)",
                    respuesta.size());
            respuestaHttp = ResponseEntity.ok(respuesta);
        } catch (DataAccessException e) {
            log.error("Error al listar los ultimos clientes", e);
            respuestaHttp = ResponseEntity.internalServerError().build();
        }

        return respuestaHttp;
    }

  Alternativa a medio plazo: apuntar facturas.js a /cliente/listar-pagina, que ya
  existe y hace lo mismo con paginación. Pero eso cambia el formato de la
  respuesta y obliga a tocar el JS, así que para dejarlo funcionando ya, lo de
  arriba.
